# 客户端语义与边界

本说明描述源码设计与 review 结果，不代表已通过构建、负载、机器人或游戏平台联调。

## 生命周期与鉴权

构造 `ClientOptions` 和 `ManagedBridgeClient` 不连接网络。首次 `start()` 启动一套受管理的后台资源，返回第一次 READY 的 future；重复调用不建立第二条连接。首次连接失败会自动退避重试，首次 READY 前的 future 不设额外总等待期限；宿主自行限制等待，放弃时调用 close。

`close()` 非阻塞且可重复；即使尚未 start 也会完成关闭。`whenClosed()` 表示协议循环结束、网络取消和自有执行器关闭已发起，不能据此认为外部平台调度的任务被强制终止。客户端关闭或永久失败后重新创建实例才可恢复。实例从创建到关闭保持同一个 boot ID；普通重连复用实例。重新创建客户端视作游戏接入实例重新启动，内存去重记录不延续，不能重试旧的未知动作。

状态为 NEW → CONNECTING → HANDSHAKING → SYNCHRONIZING（按需）→ READY；暂时断线进入 BACKOFF，永久配置 / 鉴权 / 协议错误进入 FAILED，主动关闭进入 CLOSED。HTTP 409 / 暂时网络故障按退避处理；400、401、403、404、重定向或不兼容协议停止重试。修正配置后重建客户端。

端点固定为 `ws(s)://host[:port]/bridge/v1`，拒绝 URL 凭据、查询参数、fragment 和重定向。回环以外要求 wss，保留 TLS 正常证书校验。节点 Token 只放在 Authorization header，连接时调用供应器重新取得；Token 采用 32–4096 个不含空白的可打印 ASCII 字符。Core 自动生成的凭据符合该格式。

连接 / 握手预算为 10 秒。OkHttp 自动回应 WebSocket ping，并发送 20 秒间隔 ping；Core 同样有自己的 ping 检测。Core 禁用压缩，本客户端拒绝协商出的扩展。网络库可能先将整个帧组装为字符串，随后才检查 3 MiB 限额；应用层字节配额不是堆内存硬隔离。

## 请求、取消与线程

普通请求仅在 READY 执行，超时参数为 1 毫秒至 30 秒；期限包括在客户端队列中等待的时间。服务未就绪或已关闭返回 NODE_OFFLINE / CLIENT_CLOSED，容量不足返回 BUSY。参数 / JSON 形状错误可在方法调用时直接抛出 IllegalArgumentException 或 BridgeException。

连接断开时不把旧队列带到新会话。发送后没有确定答复，统一报告 RESULT_UNKNOWN；当前客户端不自动重试请求。远端业务错误保留公开 code / message，原始网络异常、Token、聊天或背包内容不写入状态日志。

取消 future 取消调用者的等待。尚未处理的取消请求会被跳过；已经发送或已进入事件缓冲的操作不能据此认定撤销。协议没有取消远端副作用的控制消息。`start()` future 的取消同样不会停止重连，停止要调用 close。

协议处理在独立循环运行；future 通常在独立完成线程结束。已经完成的 future、调用者主动 cancel 及后续同步 continuation 遵守 CompletableFuture 自身语义，不能假设回调永远来自特定线程。状态通知在另一条有界线程队列中尽力投递，慢订阅者可能错过状态；`status()` 始终给出最新快照。

任何外部回调都必须快速返回；需 I/O、阻塞等待或复杂计算时使用自己的 `*Async` executor。库不会通过阻塞协议线程来等待用户回调，也不能强制终止不响应取消的第三方 Java 代码。游戏 / 区域线程切换由平台处理。

## 在线快照交接

Core 的每个网络只有一个会话权威节点。Core 在 welcome 中要求快照时，客户端进入 SYNCHRONIZING，调用 SnapshotProvider。平台必须使用同一个有序发布器处理快照与加入 / 离开：

1. 把捕获任务调度到负责权威玩家集合的串行调度器。
2. 读取一致的玩家集合，在该串行任务内直接调用 `sink.submit(players)`；不要收集后另起异步任务才 submit。
3. 玩家加入 / 离开同样通过该有序发布器提交给 client。

submit 之前缓冲的成员变动已经包含在新快照中，客户端以快照覆盖它们；这些 future 在快照 ack 后返回快照的确认序号。submit 之后的增量继续缓冲，收到快照 ack 后依次发送。聊天、背包和 ready 等其他缓冲事件在快照后处理。

快照最多 10000 人，不能重复玩家名，identity mode 必须匹配。捕获与确认总预算 15 秒，失败会断开并重新获取快照。非权威节点不应该发送玩家会话事件。Folia 等平台需提供自己的权威集合 / 区域数据协调，不能直接在普通工作线程遍历游戏平台对象。

事件确认 future 的上限为 15 秒；有效 ack 只表示 Core 已处理并保存游标。它不表示 QQ 消息已送达或游戏动作成功。过期或断开的聊天不会在重连后自动重放。

## 动作与去重

注册的 handler 集合就是 hello 中声明的 capabilities。Core 还会与管理员允许的 actions 取交集。不要注册实际平台不支持的能力。客户端先验证标准 payload，再在独立线程调用 handler；handler 必须立即返回 CompletionStage，在正确平台线程执行操作。

ActionRequest 包含原始 deadline 与 CancellationToken。令牌依据本地单调时钟控制预算，并考虑协议允许的 30 秒时钟偏差；平台应使用 `remaining()` / `isCancelled()`，并在真正执行副作用前再次检查。断线、关闭和超时都会取消令牌。

完成值使用有效 JsonData；没有业务返回值时返回 `JsonData.nullValue()`，不要返回 Java null。背包响应必须属于请求的同一个 Player；TPS 取实际游戏采样，无法测量时为 null。控制台命令 actor_id 是 Core 的复合身份字符串，可能含单位分隔符；它是审计元数据，不能当 shell 参数或直接作为显示名。

默认失败或回调抛异常返回 RESULT_UNKNOWN。只有确定在任何副作用之前拒绝时才可使用 ActionRejectedException 的有限错误码。不能在部分执行之后把失败改称 FORBIDDEN / BUSY 来诱导安全重试。

按 idempotency_key 和 type / payload SHA-256 保存同一客户端实例内的去重信息。相同键对应不同请求内容会被拒绝；在执行中的重复请求立即得到 RESULT_UNKNOWN，不执行第二遍。完成结果保留 5 分钟，同键重试可返回缓存结果。payload 的对象键顺序也影响摘要，复用键时必须复用相同内容。

缓存最多 4096 条，结果 JSON 总额最多 8 MiB。大结果无法再缓存时，首次调用仍返回实际结果，后续同键保留“结果未知”的占位记录，仍然不重执行。记录容量满时在调用 handler 前返回 BUSY；不会为了腾位置而提前遗忘未过期的副作用键。客户端重建 / 游戏重启后去重记录丢失，旧操作结果继续视为未知。

## 有界资源

| 资源 | 上限 / 行为 |
| --- | --- |
| 协议消息 | 3 MiB；JSON payload 2 MiB，嵌套深度 64，拒绝重复对象键 |
| 协议任务队列 | 256 项；积压接收内容最多 8 MiB |
| API 入队内容 | 最多 8 MiB；总共最多 128 个尚未完成通知的操作 |
| 普通待回复请求 | 64 个，payload 总计 8 MiB |
| 上报 / 缓冲事件 | 64 个，payload 总计 8 MiB；恢复快照另占一个内部位置 |
| WebSocket 待发字节 | 应用层最多 6 MiB；超过后断开，不在库中无限排队 |
| 游戏动作 | 最多 64 个并行等待，输入总计 8 MiB；2 个调度线程、64 个待分发位置 |
| 状态订阅 | 最多 32 个；慢订阅不阻塞网络，通知可丢弃 |
| 重连 | 约 1 秒起指数退避，基础上限 30 秒，另加小范围抖动 |
| 占位符缓存 | ExpiringValue 只保存一份不可变值，TTL 必须大于 0 且不超过 5 分钟 |

这些是协议字节与条数限制，不是整个 JVM、JSON 对象、网络库或用户回调的硬内存限额。
